Job Agent

A job search that runs itself. One reviewed facts bank replaces a pile of CVs. Every morning an agent finds and scores new postings. On request it drafts a fact-checked CV and letter, and a Chrome extension fills in the application form.

The problem

I apply across many kinds of jobs, and every part of the search was slow and easy to get wrong.

01

Too many CVs

I had written a different CV for each kind of job. I could no longer tell which facts belonged in which CV, and the versions had started to disagree with each other.Fix: one reviewed facts bank
02

Finding the right jobs

02

One facts bank

First I worked out the kinds of jobs I actually apply for. There are nine. Then I gathered every CV I had written into one file that holds every fact and every piece of work I have ever done, each with the CVs it came from.

23 CV versions collected. The 11 written in the last six months were used.

Nine categories. Each CV is built from the same bank, never from another CV.

Building the bank was the hard part, and I did it with Claude. It read every CV, lined up the same fact across versions, and flagged where they disagreed. I answered each conflict, and my answer became the rule. Where wording must stay fixed, the entry says so.

Three files, three jobs

What is trueThe master profile. The only place a CV or letter may take a fact from.master_profile.md
What to aim forA targeting file. For each category, the highest level worth showing and the most years of experience a posting can ask for. It also states how deep each skill really is, so I am not shown jobs I should not apply to.targeting.yaml
What to type into formsAn application profile. Contact details, education and jobs, each marked as verified with its source.application_profile.json

Cheap checks first

Model calls are the scarce resource, so the agent spends them only where they matter. Plain rules go first. Only what survives reaches a model, and only the best reach the stronger one.

FetchedAll new postings
Every new posting, de-duplicated
Rule filterNo AI
Title words, location, level, blockers
Quick scoreClaude Haiku
Up to 50 a day, 10 per call
Fit reportHaiku, then Sonnet
Top 5

The rule filter drops jobs by title, location and seniority, and flags wording such as a security clearance or no visa sponsorship. The quick score ranks what is left against the facts bank. The top five a day, with a quick score of at least 50, get a full report that checks each requirement in the posting against my experience.

Built on a subscription, not an API

I did not have API access, so the agent runs through my Claude subscription. That shaped how it works.

7:00A background service starts at login and runs each morning. If the laptop was asleep, it catches up.
150A hard cap on automatic Claude calls a day.
PauseWhen the usage limit is reached, work stops and picks up again when it resets.
LogEvery Claude call is recorded, so I can see what each step costs.
04

Writing applications

When I pick a job, a team of separate agents writes the application. Each has one task. They talk only through files in one folder per job, so every step can be read and checked.

01Job analystBreaks the posting into requirements. It never sees my CV, so it cannot bend the job to fit me.Haiku
02Fit scorerMatches each requirement to entries in the facts bank.Sonnet
03CV writerBuilds a CV for the job from facts bank entries only.Agent
04Letter writerDrafts the cover letter on the same rule.Agent
05Fact-checkerChecks every claim against the facts bank and returns pass or fail.Agent
One folder per job The postinginput Requirements01 Fit report02 Tailored CV03 Cover letter04 Fact-check report05
The fact-checker is adversarial. It looks for any claim that is not in the facts bank. A fail sends the draft back with the reasons, for up to two rounds of fixes.
PASSFAIL → fix

The documents are rendered to PDF with headless Chrome. Nothing reaches an employer without my review.

05

The portal

Everything lands in a local web dashboard. It is where I decide what to apply for.

See every jobAll postings with their category, score, the reasons behind the score and the deadline.
Act on oneOne button starts the agents for a job. The finished CV, letter and fact-check report appear next to it.
Tune without costEdit the targeting file and the next morning run applies it. No model calls are needed to change what I see.
06

The extension

The last slow step was the application form itself. I built a Chrome extension that fills it in from my application profile, so I only check and submit. It also sends any posting I find while browsing straight to the agent.

07

Outcome

The CV problem is solved. There is one source of truth, and every CV and letter is built from it. Searching now takes a few minutes each morning. As of October 2026 the agent had stored 2,193 postings, quick-scored 1,520 and written detailed fit reports for 127.
